# 复核与交付

## 写作时自查的高风险点

保真评测会抽查，但这些点最容易在压缩时出错，写的时候就核对原句：

- 定义、公式、代码、关键数字和单位；可执行的小算例直接运行验证。
- 指标的分母、样本、预算、时间窗口；特定案例的结论不扩大成普遍规律。
- 讲师的“我猜/据说/我的经验”不能变成事实；学生提问不清楚时以讲师复述为准。
- ASR 错误：按画面或上下文校正时，在 editor_notes 写明原转写和校正依据，不悄悄替换。
- 公式、代码、案例和现场问答没有在压缩中消失；视频帧处于完整状态，caption 不超出画面可见内容。

发现并修正的实质问题在 manifest 记 issue：问题、位置（节/原句 ID/时间/页码）、证据、修复、复核人。

## 浏览器检查

先跑 `python3 <skill>/scripts/check_html.py <run>/课堂笔记.html`：静态检查锚点/本地链接/外部资源/图片解码/阅读模式控件；有 headless Chrome 时在 390 与 1280 宽度检查溢出、脚本错误、坏图并操作模式切换和全部展开，各截一张 `qa/shot-*.png`，结果自动写入 manifest `status.browser_check`。没有浏览器时结果是 `static_only`——照实写“未测交互”，不要换各种浏览器或截屏方案反复尝试（对照实验里这一项曾吃掉 Codex 主线程一半以上的 token）。

有可交互的浏览器工具时，再人工看一遍下面几项，至少桌面（约 1280px）和手机（约 390px）两种宽度：

- 图解：文字清晰、不溢出不重叠，放大后可看原尺寸。
- 交互：“图解速读/完整笔记”切换、逐节展开、“依据第 N 条”跳转并展开、目录、自测展开收起、图片放大关闭。
- 控制台无错误；离线打开时图片与样式完整。
- 打印预览包含折叠内容（完整笔记、答案、来源）。

把检查的宽度、方法和结果写进 manifest `status.browser_check`；只截图没操作交互，就写“未测交互”。桌面窄屏模拟不等于真实手机。

## 交付

- 多课时按视频单独交付，各自给文件路径、评测分数（精度/召回/状态）和已知缺口；合集或索引页是额外选项，不是唯一入口。
- 先做一课样板，确认评测和阅读效果，再批量。
- PDF/ZIP 只在用户要求时生成：PDF 检查每个正文块和图片都进入成品、字体不缺字；ZIP 用相对链接并检查内部链接和图片。改了 notes 后重建所有已交付格式，不让新 HTML 和旧 PDF 混交。
- 用户只要文件时，不复述长篇过程日志。
