# 批量课程与断点恢复

仅在多视频、既有失败任务或后台跟进场景读取。协调者管理清单，单个 BaoCut 托管会话仍只操作它绑定的项目。

## 先有清单，再发任务

逐视频记录：稳定视频 ID/URL、标题、项目与会话、运行目录、媒体指纹、runtime job ID、各阶段状态、最后观察时间、证据、下一步、阻塞和恢复条件。不要只用“完成”一个布尔值；至少区分：媒体可读、转写、全文阅读、完整笔记、图解、保真评测、HTML 浏览器检查、PDF/包验收、交付。逐课状态以各 run 的 manifest 为准。

用户要求整门课程、播放列表或一组视频，就默认处理全部已明确纳入范围的视频，包括必要的项目创建与复用，不逐视频、逐项目请求确认。频道链接配有课程名时只纳入该课程；单视频链接不默认扩展到整个频道。仅在范围无法合理判定时询问，期间继续不依赖答案的准备工作。

先扫描已有清单、项目与 run，再补缺项。外部协调者通过厂商 CLI launcher 查询共享项目库、核对视频 ID、复用匹配项目并为缺项创建项目；按当前 `projects.md` 获取目录与命令，不猜库路径。只有需要 App 特有入口时才操作 UI。托管工作会话仍只处理各自绑定项目；批量授权不会解除宿主绑定，也不要求外部协调者必须为每课创建一个聊天会话。

记录本批范围及查询时间。默认完成查询时已发布的课程视频；新讲义不等于新视频，持续监控后续更新需用户提出。

课程推荐材料另维护 materials.json，按视频标题/授课日期映射官网课次，不假设 Part 编号一致。单课记录材料阅读与整合状态；共用论文按来源版本和哈希复用实际阅读范围。新论文/讲义或既有链接内容变化也记增量，只刷新受影响补充与导出，不触发无变化的媒体下载或 ASR。周期任务同时检查官方视频清单和阅读清单，新增视频、材料变更与历史未完成恢复分别判断。

## 判断真实进度

- CLI 退出、聊天结束或前台无响应，不能单独证明后台任务已停止。通过当前版本支持的 jobs/status/logs 查询原 job；运行/排队中的任务不另起一次。
- 媒体文件存在不等于完整可解码。下载异常先核对各流时长与尾部解码；只有音频时可继续转写和官方讲义笔记，但要在 limitations 写明画面缺口，召回评测也无法出画面题，不能把这一降级当作全部完成。
- 从最近成功阶段继续：例如转写成功而HTML失败，只重做笔记或渲染。新增补转写使用独立来源ID，保留原始转写、排除项与缺口；不要改原句ID掩盖遗漏。
- 遇到同一种错误重复出现且没有新证据时停止该重试分支。记录错误、已尝试办法和恢复触发（权限恢复、有效媒体、任务结束等）；在用户已授权范围内继续独立工作。

## 并行与先行样板

先做一课样板，打通导出、内容和用户目标阅读环境，再扩大同类交付。样板检查可与其他课的下载、转写并行，不需要无故阻塞全部准备。

多开会话不代表底层ASR并发。本次资源能力必须从运行状态观察；采用阶段流水并行：转写一课时读另一课讲义，成稿后让审查者接手。每个课程目录只允许一个当前写入者，交接后再改正文；共用桌面操作由协调者串行安排。

批量上限根据实际后台队列、GPU/网络/账户限制调整，不硬编码“并发越多越快”。不重启整个App或管理服务来试图清除单任务未知状态。

样板通过且有两课以上待整理时，使用可用子代理并行承担独立课程的全文阅读、原文核对、选图、正文和图解；保真评测交给没参与写作的另一个子代理；保留协调者完成共享台账和交付。先启动已备齐证据的课程，不要把整个批次的阅读与写作串行排队。每个子代理收到明确的视频 ID、run 目录、实际索引、推荐材料映射和完成条件，只写该 run 及其本地材料阅读记录；共用论文按版本/哈希复用已读页集合，共享 materials、manifest、index 和浏览器视口由协调者统一写入。代理回报分节数、全文阅读块/句数、原文页集合、候选/入选图数量、渲染与评测结果及剩余项；协调者应在各课就绪时收口，不等全批成稿再开始所有验收。后台 ASR 是否允许并发仍按实际队列判断；子代理写作并行不等于 GPU 并发。

最小化返工：下载/提取/哈希等独立 I/O 可有界并发；渲染、validator 与依赖收口按输入就绪执行。不要为了同步进度反复输出长转写或重跑已通过且未变化的检查。实际缺页、版本差异或失败只回查受影响范围，保留真实阅读边界和未知计量。

## 后台跟进

用户请求时才创建自动跟进，优先沿用已有任务。每次读取状态后只做可行动的增量；已交付内容不因定时触发重新下载或重写。

状态未变化时保持安静。阻塞需要用户改变权限或提供信息时，给出一次具体说明，不把安全策略拒绝当作网络故障绕路。只有实际满足用户结束条件才能停用；不能把“暂时无可行动事项”记作完成。

## 批次可追溯性

按 [可追溯运行](traceability.md) 在每课 manifest 的 log 里记录执行者、阶段尝试和实际后台 job；同一任务轮询不增加 attempt。并行性能同时记录课程工作量、复用、质量范围及返工，不能把代理数量当后台推理并发。批次状态由逐课 manifest 的最新冻结版本生成；子代理只写自己的 run，协调者维护批次视图。
